# HelloMe 智能体数量限制与停用规则方案

## 1. 背景

HelloMe 的核心商业目标是让用户持续使用智能体并消耗 Token。

因此智能体数量限制不应该设计得过重。它的作用不是阻止用户更换智能体，而是控制同一时间可使用的智能体数量。

新的原则：

> 套餐限制“同时启用的智能体数量”，用户可以随时停用智能体释放名额，再启用新的智能体。任务执行按实际 Token 消耗计费。

## 2. 产品定义

建议把套餐能力命名为：

```text
可同时启用智能体数量
```

示例：

```text
体验版：可同时启用 1 个智能体
专业版：可同时启用 3 个智能体
团队版：可同时启用 8 个智能体
```

不要强调：

```text
绑定
解绑
冷却
更换次数
```

原因：

- 这些词会让用户觉得被限制。
- 你的收益来自 Token 消耗，不来自锁死智能体。
- 允许用户更换，反而能让用户更快找到想用的智能体并开始消耗 Token。

## 3. 核心规则

### 3.1 启用规则

```text
启用一个智能体，占用 1 个智能体名额。
只有已启用智能体可以发起任务。
任务执行按实际 Token 消耗计费。
```

如果名额未满：

```text
用户可以直接启用智能体。
```

如果名额已满：

```text
用户需要先停用一个已启用智能体，或升级套餐。
```

### 3.2 停用规则

推荐规则：

```text
用户可以随时停用智能体。
停用后立即释放名额。
停用不退还已消耗 Token。
停用不删除历史任务和结果。
```

停用后的限制：

```text
不能发起该智能体的新任务。
不能继续生成。
不能重新运行历史任务。
```

允许的操作：

```text
查看历史任务
查看结果
复制结果
下载结果
查看消耗记录
```

### 3.3 执行中任务

为了避免状态混乱，执行中的任务不建议被硬停用。

推荐处理：

```text
如果该智能体有执行中任务，停用按钮仍可点击，但需要先处理任务。
```

弹窗：

```text
该智能体还有进行中的任务

停用前需要先完成或取消当前任务。已消耗的 Token 会按实际执行情况结算。

[查看任务] [取消任务并停用]
```

如果用户选择“取消任务并停用”：

```text
取消未完成任务
按已产生的实际 Token 结算
停用智能体
立即释放名额
```

## 4. 为什么不做冷却期

不建议做：

```text
10 分钟试用撤销
每月 1 次即时更换
24 小时冷却
冷却中名额
```

原因：

```text
规则复杂，普通用户难理解
用户会觉得被套路
限制更换并不会直接提升收入
用户真正开始执行任务才会消耗 Token
允许快速更换能降低试错成本
```

平台利益的保护方式应该是：

```text
任务消耗 Token 不退还
只有已启用智能体才能发起任务
同一时间可启用数量受套餐限制
执行中任务取消后按已消耗 Token 结算
```

这比冷却期更直接，也更容易被用户接受。

## 5. 用户可理解的规则

推荐对用户展示：

```text
你的套餐可同时启用 1 个智能体。
启用后即可使用该智能体发起任务，任务按实际 Token 消耗计费。
你可以随时停用当前智能体并更换为其他智能体。
停用不会删除历史任务和结果，但已消耗 Token 不会退回。
```

名额已满提示：

```text
当前套餐只能同时启用 1 个智能体。
如需启用新的智能体，请先停用当前已启用智能体，或升级套餐。
```

停用确认：

```text
停用 GEO 智能体？

停用后会立即释放 1 个智能体名额。历史任务和结果仍可查看，但你将不能继续发起 GEO 任务或重新运行 GEO 历史任务。

已消耗的 Token 不会退回。

[取消] [确认停用]
```

套餐能力：

```ts
interface PlanEntitlements {
  planName: string;
  monthlyTokenLimit: number;
  enabledAgentLimit: number;
}
```

用户智能体状态：

```ts
type AgentActivationStatus = 'inactive' | 'active' | 'readonly';

interface UserAgentActivation {
  agentId: string;
```

## 9. 判断逻辑

### 9.1 是否可以启用智能体

```text
如果智能体已启用：可直接进入使用
如果套餐不支持该智能体：提示升级
如果已启用数量小于套餐限制：可启用
如果已启用数量达到套餐限制：提示先停用或升级
```

### 9.2 是否可以停用智能体

```text
如果没有执行中任务：可立即停用并释放名额
如果有执行中任务：提示先完成或取消任务
如果用户取消任务并停用：按已消耗 Token 结算，然后释放名额
```

### 9.3 停用后还能做什么

允许：

```text
查看历史任务
查看结果
复制结果
下载结果
查看消耗记录
```

不允许：

```text
发起新任务
继续生成
重新运行
基于结果继续操作
```

重新启用后恢复这些能力。

## 10. 边界情况

### 10.1 降级套餐

如果用户降级后已启用数量超过新套餐限制：

```text
当前计费周期内保持可用。
下个周期开始时要求用户选择保留哪些智能体。
超过名额的智能体进入只读状态。
```

### 10.2 套餐过期

```text
所有智能体进入只读状态。
历史任务和结果可查看。
不能发起新任务。
续费后恢复。
```

### 10.3 Token 用尽

```text
智能体仍保持启用状态。
不能发起新的消耗型任务。
充值 Token 后继续使用。
```

## 11. 推荐落地顺序

### P0

```text
套餐展示“可同时启用智能体数量”
启用智能体占用名额
达到名额上限时提示先停用或升级
停用智能体立即释放名额
停用不删除历史任务和结果
已消耗 Token 不退回
```

### P1

```text
执行中任务的取消并停用流程
降级后的只读状态
套餐过期后的只读状态
```

### P2

```text
团队版成员维度的智能体使用统计
不同智能体的套餐可用范围
```

## 12. 最终推荐文案

官网短文案：

```text
每个套餐包含固定数量的可同时启用智能体。你可以随时停用并更换智能体；任务执行按实际 Token 消耗计费。
```

工作台说明：

```text
启用智能体会占用 1 个名额。停用后立即释放名额，历史任务和结果仍可查看，已消耗 Token 不会退回。
```

用户能理解的总结：

> 套餐决定你能同时启用几个智能体，Token 决定你能执行多少任务。智能体可以随时更换，已经消耗的 Token 按实际使用结算。
