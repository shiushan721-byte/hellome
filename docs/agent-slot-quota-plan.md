# HelloMe 智能体数量限制与取消规则方案

## 1. 背景

HelloMe 套餐需要同时限制两类资源：

```text
Token 额度：控制用户能执行多少任务、消耗多少计算资源
智能体数量：控制用户能启用多少个场景智能体
```

Token 解决的是“用多少”的问题，智能体数量解决的是“能用哪些能力”的问题。

如果不同套餐允许启用不同数量的智能体，就需要设计“添加智能体、占用数量、取消占用、重新选择”的规则。

核心目标：

```text
保护平台利益
避免用户频繁切换薅权益
让规则透明、可解释、不过分强硬
给用户合理试错空间
```

## 2. 产品定义

建议把“智能体数量限制”命名为：

```text
可启用智能体数量
```

不要叫：

```text
智能体使用次数
```

原因：

- “次数”容易和任务次数混淆。
- 用户会以为每次打开都消耗一次。
- “启用”更接近套餐能力管理，用户更容易理解。

推荐解释：

> 套餐内包含一定数量的可启用智能体。启用后，你可以在该智能体内发起任务，任务执行消耗 Token。你可以在规则允许范围内停用智能体并更换。

## 3. 套餐建议

### 3.1 套餐结构

示例：

```text
体验版：可启用 1 个智能体
专业版：可启用 3 个智能体
团队版：可启用 8 个智能体
企业版：不限或自定义
```

Token 额度仍然单独展示：

```text
体验版：50,000 Token，可启用 1 个智能体
专业版：500,000 Token，可启用 3 个智能体
团队版：3,000,000 Token，可启用 8 个智能体
```

### 3.2 智能体状态

每个智能体建议有以下状态：

```text
未启用
已启用
可停用
冷却中
套餐不可用
```

解释：

```text
未启用：不占用智能体数量
已启用：占用 1 个可启用智能体数量
可停用：允许用户停用并释放名额
冷却中：刚停用后暂时不能重新启用或更换
套餐不可用：当前套餐不支持该智能体
```

## 4. 是否支持取消

建议支持取消，但不要无限制即时切换。

推荐规则：

> 支持停用智能体并释放名额，但有冷却期和任务保护规则。

这样既不显得霸王条款，也能避免用户用 1 个智能体名额反复切换，把所有智能体都用一遍。

## 5. 推荐取消规则

### 5.1 规则一：启用后有免费试用窗口

用户第一次启用某个智能体后，在短时间内如果没有产生明显资源消耗，可以无损取消。

建议规则：

```text
启用后 10 分钟内
且未完成任何正式任务
且消耗 Token 少于 1,000
可立即停用并释放名额
```

用户感知：

```text
我点错了，可以撤销。
```

平台利益：

```text
用户没有实际深度使用，不强行占用名额，减少投诉。
```

### 5.2 规则二：正式使用后仍可停用，但进入冷却期

如果用户已经用该智能体完成任务，允许停用，但释放后的名额进入冷却期。

建议规则：

```text
完成过正式任务后，可以停用智能体。
停用后该名额 24 小时后释放。
冷却期间不能用该名额启用新的智能体。
```

也可以更温和：

```text
每个自然月有 1 次即时更换机会。
超过后，停用智能体需要等待 24 小时释放名额。
```

这是最推荐方案，用户体验更好。

### 5.3 规则三：执行中任务不能停用

如果智能体下有任务正在运行、等待确认、排队或重试，不允许停用。

提示：

```text
该智能体还有进行中的任务，请先完成或取消任务后再停用。
```

原因：

```text
防止任务状态混乱
防止用户在消耗中绕开限制
保护结果归属和计费链路
```

### 5.4 规则四：停用不删除历史任务和结果

停用智能体只影响继续发起新任务，不影响历史结果。

规则：

```text
停用后，历史任务和结果仍可查看、复制、下载。
停用后，不能基于该智能体继续生成、重新运行或发起新任务。
重新启用后恢复继续操作。
```

用户感知：

```text
我不会因为停用而丢东西。
```

平台利益：

```text
用户想继续使用该智能体能力时，需要重新占用名额。
```

## 6. 推荐最终方案

建议采用：

```text
启用名额 + 试用撤销 + 每月一次即时更换 + 24 小时冷却 + 执行中不可停用
```

完整规则：

1. 套餐包含固定数量的“可启用智能体”。
2. 启用一个智能体后，占用 1 个智能体名额。
3. 该智能体内发起任务时，按 Token 消耗计费。
4. 启用后 10 分钟内，如果没有完成正式任务，且 Token 消耗低于 1,000，可以立即停用并释放名额。
5. 每个自然月提供 1 次即时更换机会，可以停用一个已使用智能体并立即释放名额。
6. 即时更换机会用完后，停用智能体会进入 24 小时冷却期，冷却结束后释放名额。
7. 有执行中、等待确认、排队中的任务时，不能停用该智能体。
8. 停用智能体不会删除历史任务和结果，但不能继续生成、重新运行或发起新任务。
9. 升级套餐后立即增加可启用智能体数量。
10. 降级套餐后，如果已启用数量超过新套餐限制，保留当前已启用智能体到本计费周期结束；下周期需要用户选择保留哪些智能体。

## 7. 为什么这样不算霸王条款

这个规则对用户是公平的，因为：

```text
点错了可以撤销
正式用过也可以停用
每月给一次即时更换机会
停用不删除历史结果
规则提前展示
不是永久锁死
```

这个规则对平台是安全的，因为：

```text
不能无限频繁切换
执行中不能停用
用过后有冷却期
继续生成和重新运行需要重新启用
Token 仍按实际任务消耗扣除
```

## 8. 工作台页面设计

### 8.1 智能体广场

智能体卡片增加状态和操作。

未启用：

```text
GEO 智能体
预计消耗：12,000-25,000 Token / 标准任务
当前状态：未启用
[启用智能体]
```

已启用：

```text
GEO 智能体
当前状态：已启用
本月任务：12 个
本月消耗：238,000 Token
[进入智能体] [停用]
```

名额已满：

```text
可启用智能体：3 / 3
如需启用新的智能体，请停用一个已启用智能体或升级套餐。
```

按钮：

```text
[管理已启用智能体]
[升级套餐]
```

### 8.2 启用智能体确认弹窗

文案：

```text
启用 GEO 智能体？

你的专业版套餐可启用 3 个智能体，当前已启用 2 个。
启用后将占用 1 个智能体名额。该智能体内的任务会按实际 Token 消耗计费。

启用后 10 分钟内，若未完成正式任务且消耗低于 1,000 Token，可立即停用并释放名额。
```

按钮：

```text
[取消] [确认启用]
```

### 8.3 停用智能体确认弹窗

未深度使用，可立即释放：

```text
停用 GEO 智能体？

该智能体尚未完成正式任务，停用后会立即释放名额。
历史记录仍会保留。

[取消] [确认停用]
```

已深度使用，有即时更换机会：

```text
停用 GEO 智能体？

停用后你将不能继续发起 GEO 任务，也不能重新运行 GEO 历史任务。
历史任务和结果仍可查看。

你本月还有 1 次即时更换机会，本次停用会立即释放名额。

[取消] [确认停用]
```

已深度使用，无即时更换机会：

```text
停用 GEO 智能体？

停用后你将不能继续发起 GEO 任务，也不能重新运行 GEO 历史任务。
历史任务和结果仍可查看。

你本月的即时更换机会已用完。确认停用后，该名额将在 24 小时后释放。

[取消] [确认停用]
```

执行中不可停用：

```text
暂时不能停用

该智能体还有进行中的任务。请先完成或取消任务后再停用。

[查看任务]
```

### 8.4 套餐与用量页

增加“智能体名额”模块：

```text
可启用智能体
2 / 3

已启用：
GEO 智能体
自媒体智能体

本月即时更换机会：
1 / 1
```

如果有冷却：

```text
销售获客智能体已停用
名额将在 18 小时 24 分钟后释放
```

## 9. 官网套餐文案

套餐卡增加：

```text
可启用智能体数量
```

示例：

```text
专业版
¥199 / 月
包含 500,000 Token
可启用 3 个智能体

适合持续做 GEO 检测、内容生成和销售触达的个人用户。
```

说明文案：

```text
套餐内包含可启用智能体数量。启用后即可使用该智能体发起任务，任务按实际 Token 消耗计费。你可以停用智能体并更换，具体以工作台内规则为准。
```

不要写：

```text
只能绑定，不能取消
一经启用，不可更换
```

这种文案会让用户觉得像霸王条款。

## 11. 判断逻辑

### 11.1 是否可以启用智能体

```text
如果智能体已启用：可直接进入
如果套餐不支持该智能体：提示升级
如果当前已启用数量小于套餐限制：可启用
如果存在冷却中名额：提示等待释放或升级
如果已达到数量上限：提示停用其他智能体或升级
```

### 11.2 是否可以停用智能体

```text
如果有执行中任务：不可停用
如果启用后 10 分钟内且未完成任务且消耗低于 1,000 Token：立即释放名额
如果本月还有即时更换机会：立即释放名额，并消耗 1 次即时更换机会
否则：进入 24 小时冷却，冷却结束后释放名额
```

### 11.3 停用后还能做什么

允许：

```text
查看历史任务
查看结果
复制结果
下载结果
查看消耗记录
```

不允许：

```text
发起新任务
继续生成
重新运行
基于结果继续操作
使用该智能体模板
```

## 12. 边界情况

### 12.1 降级套餐

如果用户从专业版降级到体验版：

```text
当前周期内不强制停用已有智能体
下个周期开始前要求用户选择保留哪些智能体
超过名额的智能体进入只读状态
历史任务和结果仍可查看
```

提示：

```text
你的新套餐可启用 1 个智能体。当前已启用 3 个，请在下个计费周期开始前选择保留 1 个。
```

### 12.2 套餐过期

```text
所有智能体进入只读状态
历史任务和结果可查看
不能发起新任务
充值或续费后恢复
```

### 12.3 退款或异常扣费

如果任务失败或系统异常：

```text
Token 按失败规则退还
智能体启用状态不受影响
如果用户只是测试且没有完成正式任务，仍可触发试用撤销规则
```

## 13. 推荐落地顺序

### 第一步：规则和文案先统一

```text
官网套餐增加“可启用智能体数量”
工作台智能体广场增加启用状态
用量页增加智能体名额模块
```

### 第二步：实现基础启用限制

```text
启用智能体占用名额
达到上限后不能启用新智能体
已启用智能体可正常发起任务
未启用智能体不能发起任务
```

### 第三步：实现停用规则

```text
执行中不可停用
试用撤销立即释放
每月一次即时更换
超过后 24 小时冷却
```

### 第四步：处理降级和过期

```text
套餐降级保留到周期结束
下周期选择保留智能体
过期后只读
```

## 14. 最终推荐文案

官网短文案：

```text
每个套餐包含固定数量的可启用智能体。启用后即可在该场景内发起任务，任务按实际 Token 消耗计费。你可以在工作台内停用并更换智能体，每月包含一次即时更换机会。
```

工作台说明：

```text
启用智能体会占用 1 个名额。若你只是误点启用，10 分钟内且未完成正式任务可立即停用释放名额。正式使用后仍可停用，每月 1 次可立即更换，之后停用将进入 24 小时冷却。
```

用户能理解的总结：

> 套餐决定你能同时启用几个智能体，Token 决定你能执行多少任务。智能体可以更换，但不能无限频繁切换。
