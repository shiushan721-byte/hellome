# HelloMe 项目上下文与临时任务方案

## 一、背景

HelloMe 的智能体由 Hz-Hermes 执行。

Hz-Hermes 具备长期记忆和学习能力，如果用户持续在同一个智能体里处理不同品牌、不同客户或不同业务目标，容易出现上下文串扰。

例如：

```text
用户先用 GEO 智能体分析 A 品牌
又用 GEO 智能体分析 B 品牌
如果没有上下文边界，Hermes 可能把 A 品牌资料带入 B 品牌任务
```

因此 HelloMe 需要引入“项目”概念，用来隔离上下文、沉淀资料，并让多个智能体围绕同一个业务目标协同工作。

## 二、核心结论

HelloMe 需要同时支持两种使用方式：

```text
项目任务
临时任务
```

项目任务用于长期业务场景。

临时任务用于一次性、快速、不沉淀资料的场景。

本方案明确：

> 临时任务不支持“加入项目”。用户在发起任务时选择项目，就进入项目上下文；不选择项目，就作为一次性临时会话执行。

## 三、产品结构

整体结构：

```text
用户
  ↓
项目，可选
  ↓
智能体
  ↓
任务
  ↓
成果
```

项目不是替代智能体页面，也不是统一表单。

每个智能体仍然保留自己的固定页面和入参结构：

```text
GEO 智能体有自己的 GEO 入参
视频智能体有自己的视频入参
销售智能体有自己的销售入参
内容智能体有自己的内容入参
```

项目只作为共享数据层，为智能体页面提供可复用资料和上下文边界。

## 四、项目任务

### 4.1 定义

项目任务是用户在某个项目下发起的智能体任务。

例如：

```text
项目：省心家政增长项目
智能体：GEO 智能体
任务：检测品牌 AI 可见度
```

### 4.2 项目任务特点

```text
归属某个项目
读取项目资料
可以自动预填智能体表单
任务结果沉淀回项目
成果归属项目
Hermes 记忆按项目隔离
后续其他智能体可以复用项目资料
```

### 4.3 项目资料

项目资料用于描述一个品牌、客户、活动或业务目标。

第一版项目资料建议包括：

```text
项目名称
品牌名
官网 URL
产品 / 服务介绍
目标客户
核心关键词
竞品
品牌卖点
常用语气
补充说明
上传文件
历史任务
历史成果
```

### 4.4 项目资料如何进入智能体页面

用户进入智能体页面后，如果选择了项目，系统读取项目资料，并对当前智能体表单做自动填充。

规则：

```text
能确定的字段自动填
能推断的字段给推荐
不能确定的字段留空
用户始终可以修改
```

示例：

GEO 智能体表单：

```text
品牌名：从项目资料自动填
官网 URL：从项目资料自动填
核心关键词：从项目资料自动填
竞品名称：从项目资料自动填
检测范围：用户选择
检测深度：用户选择
```

视频智能体表单：

```text
品牌名：从项目资料自动填
产品 / 服务介绍：从项目资料自动填
产品卖点：根据项目资料推荐
目标人群：从项目资料自动填或推荐
视频类型：用户选择
视频风格：用户选择
时长：用户选择
平台：用户选择
```

## 五、临时任务

### 5.1 定义

临时任务是用户不选择项目，直接使用智能体发起的任务。

例如：

```text
用户进入视频智能体
不选择项目
直接填写表单并开始生成
```

### 5.2 临时任务特点

```text
不归属项目
不读取项目资料
不写入项目资料
每次使用都是新会话
Hermes 不复用项目记忆
任务完成后只保留任务记录和成果
适合快速试用、一次性生成、临时需求
```

### 5.3 临时任务不支持加入项目

第一版不做“加入项目”功能。

原因：

```text
临时任务定位是一次性使用
项目任务和临时任务在发起时就明确分流
避免用户后续再理解“同步资料、同步成果、仅关联任务”等复杂选项
避免把项目资料污染成用户没有提前确认过的内容
降低第一版实现复杂度
```

临时任务完成后，仍然可以在任务中心和成果中心查看。

但不提供：

```text
加入已有项目
创建项目并加入
同步输入资料到项目
同步生成结果到项目
仅关联任务到项目
```

如果用户希望资料沉淀到项目，应在发起任务前选择项目。

## 九、Hermes 上下文规则

Hermes 上下文必须按任务类型隔离。

### 9.1 项目任务上下文

项目任务使用：

```text
userId + projectId + agentId
```

作为上下文边界。

含义：

```text
同一用户
同一项目
同一智能体
可以延续项目内记忆
```

同一项目下的不同智能体可以共享项目资料，但各智能体的执行记忆仍应有自己的 agentId 边界。

### 9.2 临时任务上下文

临时任务使用：

```text
userId + temporarySessionId + agentId
```

作为上下文边界。

规则：

```text
每次临时任务生成一个新的 temporarySessionId
临时任务之间不共享记忆
临时任务不读取项目资料
临时任务不写入项目资料
```

### 9.3 记忆隔离原则

```text
不同项目之间记忆隔离
项目任务和临时任务之间记忆隔离
不同临时任务之间记忆隔离
同一项目内可以共享项目资料
同一项目内不同智能体按需读取项目资料
```

## 十、智能体页面交互

每个智能体页面保留自己的固定结构。

页面顶部增加项目选择区域。

### 10.1 项目选择区域

展示：

```text
当前项目：未选择
选择项目
新建项目
直接临时使用
```

选择项目后：

```text
读取项目资料
自动填充可复用字段
给出可推断字段建议
缺失字段留空
用户确认后发起项目任务
```

不选择项目时：

```text
用户直接填写当前表单
系统发起临时任务
生成新的 temporarySessionId
任务不归属任何项目
```

### 10.2 表单字段处理规则

字段分为三类：

```text
直接复用字段
智能推荐字段
用户选择字段
```

直接复用字段：

```text
品牌名
官网 URL
产品 / 服务介绍
目标客户
核心关键词
竞品
```

智能推荐字段：

```text
产品卖点
内容方向
视频主题
销售切入点
FAQ 问题
用户痛点
```

用户选择字段：


## 十三、最终定义

> 项目是 HelloMe 的业务上下文容器，用来隔离 Hermes 记忆、复用项目资料，并让多个智能体围绕同一个目标协同工作。用户也可以不选择项目直接临时使用智能体；临时任务是一次性会话，不读取项目资料、不写入项目资料，也不支持加入项目。
