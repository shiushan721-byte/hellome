# HelloMe 我的工作台与智能体顶部标签方案

## 1. 老板想法总结

老板希望把原来的：

```text
首页
我的智能体
```

合并成一个新的默认入口：

```text
我的工作台
```

“我的工作台”不是传统首页，也不是一个智能体列表页，而是用户已经启用智能体的工作空间。

核心想法：

> 用户打开我的工作台后，看到的是自己已经启用的所有智能体。每个智能体像一个顶部标签页，点开后直接进入该智能体的工作台页面。

类比：

```text
钉钉的聊天会话栏：每个会话是一个可进入的工作对象
浏览器标签页：可以打开多个、关闭、排序、切换
```

但区别是：

```text
不放在左侧
放在页面顶部
每个标签对应一个已启用智能体
标签可关闭
标签可拖拽排序
标签可置前
```

## 2. 信息架构变化

原结构：

```text
/app              首页
/app/agents       智能体市场 / 我的智能体
/app/tasks        任务中心
/app/usage        用量
/app/settings     设置
```

建议调整为：

```text
/app              我的工作台
/app/agents       智能体市场
/app/tasks        任务中心
/app/usage        用量
/app/settings     设置
```

左侧导航或主导航命名：

```text
我的工作台
智能体市场
任务中心
用量
设置
```

其中：

```text
我的工作台 = 已启用智能体的使用入口
智能体市场 = 发现和启用更多智能体
用量 = 查看 Token 余额、消耗明细和智能体消耗排行
```

## 3. 我的工作台核心结构

我的工作台不是一个独立内容页，也不是智能体卡片聚合页。

它应该是一个应用壳层：

```text
置顶导航栏
智能体标签栏
当前智能体工作台页面
```

用户进入 `/app` 后，系统应直接打开一个智能体工作台，例如 GEO 智能体工作台。不要先展示一个“我的工作台”过渡页。

```text
┌──────────────────────────────────────────────┐
│ 置顶导航栏：通知 / Token / 用户                │
├──────────────────────────────────────────────┤
│ 智能体标签栏：[GEO x] [自媒体 x] [+]           │
├──────────────────────────────────────────────┤
│ GEO 智能体工作台                               │
│ 品牌输入 / 检测设置 / 当前任务 / 最近结果       │
└──────────────────────────────────────────────┘
```

智能体标签栏直接放在置顶导航栏下面，参考 Google Chrome 标签页交互。

每个标签代表一个智能体工作台：

```text
GEO 智能体
自媒体智能体
销售获客智能体
```

点击某个标签后，下方内容区直接切换为该智能体的真实工作台页面。

明确不要出现：

```text
我的工作台标题卡片
已启用智能体聚合卡片
进入工作台按钮
“GEO 智能体卡片 -> 再点进入工作台”的二次跳转
```

正确路径：

```text
打开 /app
直接看到 GEO 智能体工作台
顶部标签栏可切换到其他已启用智能体
```

## 4. 顶部智能体标签栏

标签栏位置：

```text
置顶导航栏正下方
智能体页面内容正上方
全局应用壳内
```

它不是页面内容的一部分，而是类似浏览器标签栏的全局工作区导航。

视觉参考：

```text
[ GEO 智能体  x ][ 自媒体智能体  x ][ 销售获客  x ][ + ]
```

当前激活标签：

```text
背景更亮或边框更强
与下方页面内容形成连接
```

非激活标签：

```text
弱化显示
仍可点击切换
```

### 4.1 标签来源

标签只来自：

```text
已启用智能体
```

不展示：

```text
未启用智能体
即将开放智能体
套餐不可用智能体
```

这些仍然放在智能体市场里。

### 4.2 标签能力

每个智能体标签支持：

```text
点击切换
关闭
拖拽排序
置前
显示任务状态
显示等待确认提醒
```

标签示例：

```text
[ GEO 智能体 · 执行中 x ]
[ 自媒体智能体 x ]
[ 销售获客智能体 · 待确认 x ]
[ + 添加智能体 ]
```

标签点击逻辑：

```text
点击 GEO 标签 -> 直接显示 GEO 工作台
点击自媒体标签 -> 直接显示自媒体工作台
点击销售获客标签 -> 直接显示销售获客工作台
```

不需要中间页，也不需要智能体卡片确认。

### 4.3 关闭标签的含义

这里需要特别定义清楚。

建议：

> 关闭标签 = 从我的工作台隐藏该智能体标签，不等于停用智能体。

原因：

- 浏览器标签页里的关闭是“关闭显示”，不是取消账号权益。
- 如果关闭就等于停用，用户容易误操作。
- 停用会影响套餐名额，应该是一个更明确的管理动作。

关闭标签后的状态：

```text
智能体仍然保持启用
不释放智能体名额
历史任务和结果不受影响
可以从“+ 添加 / 管理标签”重新显示
```

如果产品希望关闭就释放名额，则必须把按钮文案改成：

```text
停用
```

不建议用 `x` 承载停用。

## 5. 启用、显示、停用三层概念

为了避免混乱，需要拆成三层：

### 5.1 启用

```text
启用智能体 = 占用套餐智能体名额，可以发起任务。
```

发生位置：

```text
智能体市场
```

### 5.2 显示在工作台

```text
显示在工作台 = 出现在顶部标签栏，方便快速切换。
```

不一定影响套餐名额。

### 5.3 停用

```text
停用智能体 = 释放套餐智能体名额，不能继续发起该智能体任务。
```

发生位置：

```text
智能体市场
我的工作台的智能体设置菜单
```

停用需要确认弹窗，不用顶部标签的关闭按钮直接完成。

## 6. 标签排序与置前

老板提到：

```text
可以关闭
可以排在前面
支持拖拽
类似打开多个浏览器网页
```

建议规则：

```text
用户可以拖拽顶部智能体标签排序。
排序保存在用户偏好中。
最近使用的智能体可以自动置前，但不要覆盖用户手动排序。
```

推荐优先级：

```text
用户手动置顶
用户手动排序
最近活跃状态提醒
默认启用顺序
```

标签菜单：

```text
置顶
移到最前
从工作台隐藏
停用智能体
```

其中：

```text
从工作台隐藏：不释放名额
停用智能体：释放名额，需要确认
```

## 7. 智能体工作台内容

点开某个智能体标签后，不进入“上一次任务”，也不只是新建任务页，而是进入该智能体自己的工作台。

这个智能体工作台就是页面主体，不再外面包一层“我的工作台卡片”。

例如 GEO 智能体：

```text
顶部：GEO 智能体工作台
左侧或上方：任务输入区
中部：当前任务状态
右侧或下方：最近结果 / 最近任务
```

建议智能体工作台遵循规则：

```text
如果有未完成任务：优先展示继续任务入口
如果没有未完成任务：默认展示新任务输入
最近已完成任务：作为辅助入口展示
历史任务：跳任务中心筛选该智能体
```

GEO 示例：

```text
GEO 智能体

[品牌名] [官网 URL] [关键词] [开始检测]

当前任务：
无进行中任务

最近结果：
HelloMe AI 可见度检测，已完成
[查看结果] [重新运行]
```

如果有等待确认任务：

```text
GEO 智能体

当前有 1 个任务等待确认
[继续任务]

也可以：
[开始新任务]
```

## 8. “+ 添加智能体”入口

顶部标签栏末尾建议放：

```text
[+ 添加智能体]
```

点击后进入：

```text
/app/agents
```

也就是智能体市场。

如果智能体名额已满：

```text
当前套餐可同时启用 1 个智能体，名额已满。
你可以停用一个已启用智能体，或升级套餐。

[管理已启用] [升级套餐]
```

如果还有空位：

```text
去智能体市场选择一个智能体启用。
```

## 9. 错误示例与正确示例

### 9.1 错误示例

不要做成：

```text
我的工作台页面
  - 已启用智能体数量卡片
  - Token 卡片
  - GEO 智能体卡片
      - 进入工作台按钮
      - 查看最近结果按钮
      - 任务历史按钮
```

问题：

```text
用户已经在我的工作台，却还要再点一次“进入工作台”
GEO 变成了卡片入口，而不是直接可用的工作台
顶部标签像普通按钮，不像浏览器标签页
页面多了一层不必要的中转
```

### 9.2 正确示例

应该做成：

```text
置顶导航栏
  - 剩余 Token
  - 用户信息

智能体标签栏
  - GEO 智能体
  - 自媒体智能体
  - 销售获客智能体
  - + 添加

页面主体
  - 当前选中智能体的真实工作台
```

如果当前选中 GEO：

```text
页面主体直接是 GEO 智能体工作台：
品牌名
官网 URL
关键词
检测模型
检测深度
开始检测
进行中任务
最近结果
```

一句话：

> 标签下面直接就是智能体页面，不要再放一个智能体卡片入口。

## 10. 我的工作台空状态

如果用户没有启用任何智能体：

```text
我的工作台还没有智能体

先启用一个智能体，开始你的第一个任务。

[去智能体市场]
```

推荐优先展示：

```text
GEO 智能体
自媒体智能体
销售获客智能体
```

但真正启用仍然发生在智能体市场。

## 11. 与智能体市场的关系

智能体市场仍然保留原逻辑：

```text
浏览所有智能体
分类筛选
搜索
启用智能体
查看已启用状态
名额满时引导停用或升级
```

我的工作台负责：

```text
展示已启用且显示在工作台的智能体
快速切换智能体
进入具体智能体工作台
处理进行中任务
开始新任务
查看最近结果
```

一句话：

> 智能体市场负责“添加能力”，我的工作台负责“使用能力”。

## 12. 页面职责分工

最终建议把“使用、启停、用量”分成三层，避免一个页面承担太多管理职能。

### 12.1 我的工作台

定位：

```text
使用智能体
```

负责：

```text
展示已启用智能体顶部标签
切换智能体工作台
发起新任务
继续未完成任务
查看最近结果
展示轻量状态概览
```

轻量状态概览：

```text
已启用智能体 1 / 1
剩余 Token 183,240
本月已用 316,760
```

不建议在我的工作台承担：

```text
完整 Token 消耗明细
复杂账单
智能体市场浏览
批量启用 / 停用管理
```

### 12.2 智能体市场

定位：

```text
添加、启用、停用智能体
```

负责：

```text
展示全部智能体
搜索和分类筛选
启用智能体
查看智能体是否已启用
停用智能体
名额满时引导停用或升级
```

停用建议优先放在智能体市场。

原因：

```text
用户换智能体时，本来就在市场里浏览新智能体。
如果名额满了，可以在市场里完成“停一个、开一个”。
这比去用量页或隐藏在工作台里更顺。
```

市场中的已启用智能体卡片：

```text
GEO 智能体
状态：已启用

[进入工作台]
[停用]
```

名额已满时：

```text
你的套餐只能同时启用 1 个智能体。
请先停用 GEO 智能体，或升级套餐。

[停用 GEO 智能体] [升级套餐]
```

### 12.3 用量页面

定位：

```text
查看 Token 余额、消耗趋势和消耗明细
```

负责：

```text
剩余 Token
本月已用 Token
本月总额度
各智能体 Token 消耗排行
任务消耗明细
充值入口
套餐升级入口
```

用量页面不建议承担：

```text
启用智能体
停用智能体
切换工作台标签
```

原因：

```text
用量页面是账单和消耗视角。
停用智能体是能力管理视角。
把停用放进用量页会让用户觉得像扣费控制，而不是智能体选择。
```

### 12.4 三层职责总结

```text
我的工作台：使用智能体
智能体市场：启用 / 停用智能体
用量页面：查看 Token 消耗和账单
```

## 13. Token 用量展示方案

### 13.1 我的工作台轻量展示

我的工作台只展示轻量用量，不展示完整明细。

建议放在工作台顶部：

```text
已启用智能体 1 / 1
剩余 Token 183,240
本月已用 316,760
```

点击 Token 区域：

```text
跳转 /app/usage
```

### 13.2 智能体市场轻量展示

智能体市场只展示：

```text
当前套餐
已启用智能体数量
剩余 Token
每个智能体预计 Token 消耗
```

示例：

```text
GEO 智能体
预计 8,000-30,000 Token
```

不展示详细账单。

### 13.3 用量页面完整展示

用量页面展示完整明细：

```text
剩余 Token：183,240
本月已用：316,760
本月总额度：500,000
```

智能体消耗排行：

```text
GEO 智能体：238,000 Token
自媒体智能体：42,000 Token
销售获客智能体：0 Token
```

任务消耗明细：

```text
时间
任务名称
智能体
预估 Token
实际消耗 Token
状态
```

示例：

```text
2026-06-17 14:22
检测 HelloMe 的 AI 可见度
GEO 智能体
预估 12,000-25,000
实际 21,640
已完成
```

## 14. 推荐路由

```text
/app                         自动打开默认智能体工作台
/app?agent=geo               直接打开 GEO 智能体工作台
/app?agent=media             直接打开自媒体智能体工作台
/app/agents                  智能体市场
/app/tasks                   任务中心
/app/tasks/:id               任务详情
/app/usage                   用量
```

如果用户点击顶部标签：

```text
只更新当前打开的 agent 参数
不离开 /app
不显示过渡页
```

示例：

```text
/app?agent=geo
/app?agent=sales
```

默认打开智能体优先级：

```text
URL 指定 agent
上次打开的智能体
有等待确认任务的智能体
第一个置顶智能体
第一个已启用智能体
```

如果没有任何已启用智能体，才展示空状态：

```text
你还没有启用任何智能体
[去智能体市场]
```

## 16. 交互规则

### 16.1 点击标签

```text
切换下方智能体工作台内容
更新 URL agent 参数
不重新加载整个应用
```

### 16.2 关闭标签

```text
从顶部标签栏隐藏
不释放智能体名额
不删除任务
不影响启用状态
```

关闭确认可以不做，提供撤销提示即可：

```text
已从工作台隐藏 GEO 智能体。
[撤销]
```

如果用户关闭了所有智能体标签：

```text
不要显示空白页
不要跳转智能体市场
显示已启用智能体卡片列表
点击“使用智能体”重新打开对应标签
```

详细方案见：

```text
docs/workbench-tab-empty-state-plan.md
```

### 16.3 停用智能体

停用优先在智能体市场完成，也可以在工作台标签菜单中提供入口：

```text
停用后释放名额
不能继续发起该智能体任务
历史任务和结果仍可查看
已消耗 Token 不退回
```

需要确认：

```text
停用 GEO 智能体？

停用后会立即释放 1 个智能体名额。历史任务和结果仍可查看，但你将不能继续发起 GEO 任务、继续生成或重新运行 GEO 历史任务。

已消耗 Token 不会退回。

[取消] [确认停用]
```

### 16.4 拖拽排序

```text
用户可拖拽顶部标签改变顺序
排序立即保存
下次进入工作台保留
```

### 16.5 置顶

```text
置顶智能体排在普通智能体前面
多个置顶智能体内部仍支持拖拽排序
```

## 17. 开发优先级

### P0

```text
将 /app 默认页改为我的工作台
把首页和我的智能体合并
在置顶导航栏下方增加浏览器式智能体标签栏
/app 直接打开默认智能体工作台
/app?agent=geo 直接打开 GEO 工作台
点击标签直接切换到对应智能体工作台
禁止出现“我的工作台聚合卡片过渡页”
```

## 18. 需要确认的问题

### 18.1 关闭标签是否等于停用？

推荐：

```text
关闭标签不等于停用。
```

理由：

```text
关闭是界面行为，停用是权益行为。
这两个动作如果混在一起，用户容易误操作。
```

### 18.2 工作台是否展示隐藏的智能体？

推荐：

```text
隐藏的不展示在顶部标签栏，但在“管理工作台标签”里可重新显示。
```

### 18.3 默认打开哪个智能体？

推荐优先级：

```text
URL 指定 agent
上次打开的智能体
有等待确认任务的智能体
第一个置顶智能体
第一个已启用智能体
```

### 18.4 停用入口放在哪里？

推荐：

```text
主要放在智能体市场。
工作台标签菜单可提供入口，但不是主入口。
用量页面不放停用。
```

理由：

```text
市场负责能力启停。
工作台负责使用。
用量页面负责账单和消耗。
```

## 19. 最终表达

> 我的工作台不是传统首页，而是用户已启用智能体的顶部标签工作区。每个智能体像一个可切换的浏览器标签页，点开就是对应智能体的工作台；智能体市场负责添加能力，我的工作台负责使用能力。
