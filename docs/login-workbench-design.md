# HelloMe 登录后工作台设计

## 1. 产品定位

HelloMe 登录后的产品不应该是传统 SaaS 后台，而应该是一个任务驾驶舱。

用户进入工作台后的核心动作不是管理资料，而是立刻发起任务、查看智能体执行过程、拿到可交付结果，并在任务中心沉淀历史记录。

核心产品表达：

> 首页发起任务，智能体执行任务，左边展示过程，右边交付结果，任务中心沉淀历史，用量套餐完成计费。

与普通 AI 聊天产品的区别：

```text
普通 AI：用户提问，模型回答
HelloMe：用户下任务，智能体执行，过程可见，结果可交付
```

## 2. 登录后信息架构

第一版登录后主导航建议保留 6 个一级入口：

```text
首页
智能体
任务中心
结果
用量
设置
```

授权管理第一版不建议作为一级导航，可以先放在设置中，或者在任务执行页出现高风险动作时通过确认节点弹出。

建议路由结构：

```text
/                 官网首页
/login            登录页
/app              登录后首页
/app/agents       智能体列表
/app/agents/geo   GEO 智能体配置页
/app/tasks        任务中心
/app/tasks/:id    任务执行与结果页
/app/results      结果中心，MVP 可后置
/app/usage        用量套餐
/app/settings     设置
/app/settings/auth 授权管理
```

MVP 阶段建议先实现：

```text
/app
/app/agents
/app/agents/geo
/app/tasks
/app/tasks/:id
/app/usage
/app/settings
```

暂时后置：

```text
/app/results
/app/team
/app/notifications
/app/api-keys
```

## 4. 登录后首页

首页目标：

> 让用户 10 秒内发起一个任务。

首页不要做成管理后台，也不要塞太多解释性内容。用户已经登录，不需要再次被教育产品是什么。

首页模块：

```text
顶部欢迎区
自然语言任务输入框
推荐智能体
常用任务模板
最近任务
用量概览
```

推荐布局：

```text
┌────────────────────────────────────────────┐
│ 今天想让智能体完成什么？                    │
│ [ 帮我检测某品牌在 AI 搜索里的可见度... ]     │
│                    [推荐智能体] [开始任务]   │
├────────────────────────────────────────────┤
│ 常用任务                                    │
│ [检测品牌 AI 可见度] [生成 GEO 优化建议]      │
│ [写公众号文章] [分析客户网站] [生成销售私信]   │
├──────────────────────┬─────────────────────┤
│ 最近任务              │ 用量概览             │
│ GEO 检测 进行中        │ Token 余额 ¥83.20    │
│ 公众号文章 已完成       │ GEO 18 / 20          │
└──────────────────────┴─────────────────────┘
```

首页重点：

- 自然语言输入是第一入口。
- 智能体推荐是辅助入口。
- 常用任务模板帮助用户快速开始。
- 最近任务让用户能继续执行或查看结果。
- 用量概览让用户知道剩余额度和本月消耗。

## 5. 智能体广场

智能体广场目标：

> 让用户知道 HelloMe 能完成哪些场景任务，并进入对应智能体。

MVP 不建议做成复杂市场型广场，先做成工作场景列表。

智能体卡片字段：

```text
智能体名称
一句话说明
适合任务
预计耗时
预计消耗
使用按钮
```

示例：

```text
GEO 智能体
检测品牌在 DeepSeek、豆包、Kimi 等 AI 回答里的可见度。

适合：品牌检测 / 竞品分析 / 官网优化
预计耗时：3-8 分钟
预计消耗：1 次 GEO 检测
[开始使用]
```

第一版智能体：

```text
GEO 智能体：完整可用
自媒体智能体：基础入口或即将开放
销售获客智能体：基础入口或即将开放
```

第一版要突出 GEO，不要平均用力。

## 6. GEO 智能体页

GEO 智能体是第一版 MVP 的核心智能体。

路由：

```text
/app/agents/geo
```

页面目标：

> 收集检测参数，并启动 GEO 检测任务。

表单字段：

```text
品牌名 *
官网 URL *
核心关键词
竞品名称
检测模型
检测深度
```

检测模型默认多选：

```text
DeepSeek
豆包
Kimi
通义
文心
腾讯元宝
```

检测深度：

```text
快速检测：约 1-2 分钟，消耗低
标准检测：约 3-5 分钟，推荐
深度检测：约 8-15 分钟，结果更完整
```

提交后创建任务，并跳转到统一任务执行页：

```text
/app/tasks/:id
```

## 7. 统一任务执行页

这是 HelloMe 登录后最重要的产品页面。

路由：

```text
/app/tasks/:id
```

页面目标：

> 左边展示 Hz-Hermes 执行过程，右边交付任务结果。

固定左右布局：

```text
┌──────────────────────┬──────────────────────────┐
│ 左：执行过程           │ 右：结果交付              │
├──────────────────────┼──────────────────────────┤
│ 任务信息               │ 结果摘要                  │
│ 当前步骤               │ 核心指标                  │
│ 步骤列表               │ 模型表现对比              │
│ Hz-Hermes 操作日志         │ 内容缺口                  │
│ 等待用户确认            │ 优化建议                  │
│ 控制按钮               │ 复制 / 下载 / 继续生成      │
└──────────────────────┴──────────────────────────┘
```

左侧执行过程包含：

```text
任务名称
任务状态：执行中 / 等待确认 / 已完成 / 失败
当前步骤
步骤时间线
Hz-Hermes 操作日志
中间结果
错误提示
用户确认节点
任务控制按钮
```

GEO 任务步骤示例：

```text
生成检测问题
调用模型检测
分析品牌出现率
分析 AI 推荐率
分析竞品占位
识别内容缺口
生成优化建议
生成报告
```

Hz-Hermes 日志示例：

```text
[12:01] 已生成 24 个检测问题
[12:02] 正在检测 Kimi
[12:03] 发现竞品出现率较高
[12:04] 正在生成内容缺口清单
```

右侧 GEO 结果包含：

```text
AI 可见度报告
品牌出现率
AI 推荐率
竞品占位率
模型表现对比
高价值问题覆盖情况
竞品占位分析
内容缺口列表
优化优先级
可执行任务清单
FAQ 生成
LLMs.txt 生成
官网文案生成
结构化内容生成
```

结果操作：

```text
复制摘要
导出报告
生成 FAQ
生成 LLMs.txt
生成官网优化文案
重新运行
复制任务
```

这个页面要避免做成聊天窗口。它应该像一个自动化任务看板。

## 9. 结果中心

结果中心建议作为 P1 或 P2 功能。

原因：

第一版任务中心已经能承载结果查看，如果过早拆出结果中心，信息架构会变重。

如果第一版必须做结果中心，可以做轻量版本。

## 10. 用量与套餐

用量页面目标：

> 让用户知道还剩多少额度，以及每个任务花了多少。

路由：

```text
/app/usage
```

顶部四张卡：

```text
当前套餐
Token 余额
本月消耗
剩余任务次数
```

用量示例：

```text
GEO 检测次数：18 / 20
内容生成次数：7 / 10
销售线索分析：120 / 500
Token 余额：¥83.20
```

任务消耗明细字段：

```text
时间
任务名称
智能体
消耗类型
消耗数量
```

用户最关心两件事：

```text
我还剩多少
这次任务花了多少
```

因此任务开始前也要展示消耗预估。

## 11. 授权与安全确认

第一版不要做过重的第三方授权中心，先做好高风险动作确认。

三层机制：

### 11.1 任务开始前提示

示例：

```text
本任务将访问公开网页，不会执行发布、提交、删除等高风险动作。
```

### 11.2 高风险动作前确认

示例：

```text
Hz-Hermes 即将打开公众号后台并准备发布内容，是否继续？

[取消] [确认继续]
```

高风险动作包括：

```text
发布内容
提交表单
删除内容
修改文件
发送消息
导出数据
打开第三方后台
```

### 11.3 设置中展示授权状态

示例：

```text
浏览器自动化：已开启
本地文件访问：未开启
公众号：未登录
小红书：未登录
飞书：未连接
邮箱：未连接
```

MVP 里把确认节点做好，比把授权管理做全更重要。

## 14. MVP 开发顺序

建议按以下顺序开发：

1. 搭建 `/app` 登录后壳子，包括 Sidebar、Topbar 和首页。
2. 实现 `/app/agents/geo` 的 GEO 表单。
3. 接入现有 `/api/check-brand` 接口。
4. 实现 `/app/tasks/:id` 左右布局，并模拟执行步骤。
5. 把任务保存到前端状态或 localStorage。
6. 实现 `/app/tasks` 历史任务列表。
7. 实现 `/app/usage` 静态用量页。
8. 补充 `/app/settings` 和基础授权状态展示。

这样最快能得到完整演示闭环：

```text
首页输入任务
选择 GEO 智能体
开始检测
查看 Hz-Hermes 执行过程
拿到 GEO 报告
任务中心可回看
用量页面可查看消耗
```

## 16. 第一版验收标准

第一版登录后工作台至少满足：

```text
用户可以进入 /app 首页
用户可以从首页或智能体列表进入 GEO 智能体
用户可以填写品牌名、官网、关键词、竞品并开始检测
系统可以展示 Hz-Hermes 执行过程
系统可以展示 GEO 报告结果
任务可以在任务中心回看
用量页面可以展示剩余额度和消耗明细
高风险动作有确认节点设计
```

第一版产品目标：

> 让用户 10 秒内发起一个任务，1 分钟内看到过程，几分钟内拿到一个像样的结果。
