# HelloMe 前台设计统一规范

## 1. 目标

这份规范用于统一 HelloMe 前台产品的页面结构、信息密度、交互层级和组件语义。

目标不是做“好看但不一致”的页面，而是建立一套接近大厂产品的前台规范：

- 同样的功能，只用同一种交互方式
- 能极简就极简
- 默认不打扰用户
- 用户只为结果买单
- 只有在用户主动选择时，系统才展开更多信息

## 2. 产品判断

HelloMe 前台必须坚持：

- 普通用户不是来“参与创作流程”的
- 普通用户不是来“审核中间过程”的
- 普通用户不是来“理解 Skill / Agent / Prompt”的
- 普通用户是为了“用最少的钱尽快拿到最接近目标的结果”

所以前台设计原则应为：

- `默认展示结果`
- `默认隐藏过程`
- `默认压缩说明`
- `默认减少选择`
- `只在用户主动展开时展示更多信息`

## 3. 页面层级

前台页面统一分为三层：

### 3.1 默认层

用户第一眼必须只看到：

- 我要得到什么
- 我要补什么最少输入
- 系统预计产出什么
- 大概多久
- 大概要花多少

这一层不应该出现：

- 过多说明性注释
- 脚本全量内容
- 分镜全量结构
- Prompt / Skill / 路由策略细节
- 技术状态解释

### 3.2 可展开层

用户点击后才可以看到：

- 生成依据
- 中间理解结果
- 脚本草案
- 分镜预演
- 执行步骤
- 成本拆解

这一层是：

- `按需展开`
- `用户主动触发`
- `不抢占首屏`

### 3.3 专业层

只给创作者或高级角色：

- Skill 配置
- 路由策略
- Prompt / 理解配置
- 调试日志
- 版本管理

这一层不应该出现在普通用户前台主流程中。

## 4. 统一布局规范

### 4.1 工作台统一采用左中右三栏逻辑

无论是否视觉上严格三列，信息结构必须遵守三栏心智：

1. `左栏 = 输入`
2. `中栏 = 结果预览`
3. `右栏 = 状态 / 交付 / 按需展开信息`

### 4.2 三栏职责不能混

#### 左栏

只放：

- 最少必要输入
- 上传
- 平台选择
- 效果选择
- 触发主动作

左栏不放：

- 大段说明
- 复杂过程
- 大块中间结果

#### 中栏

只放：

- 结果预演
- 视觉预览
- 核心价值表达

中栏是整个页面的视觉焦点。

#### 右栏

只放：

- 交付内容
- 成本
- 状态
- 折叠后的中间依据

右栏默认应收敛，不能成为第二个主舞台。

## 5. 信息收敛规则

### 5.0 前台文案白名单

普通用户前台默认只允许出现这五类文案：

- 标题
- 状态
- 金额 / 时间
- 文件 / 结果名
- 动作按钮

超出这五类的文案，默认判定为待删除对象。

只有下面两类可以例外保留：

- 风险提示
- 输入辅助

如果一段文案是在回答这些问题，就不该留在普通用户前台：

- 系统为什么这样做
- 我们的产品逻辑是什么
- 技术链路怎么跑
- 这个模块承担什么职责
- 为什么现在要看这个

### 5.1 默认只展示一层信息

每个区域首屏只允许回答一个问题：

- 这是什么
- 我要做什么
- 我会得到什么

不能一个区域同时回答五个问题。

### 5.2 注释规则

注释不是默认常驻内容。

允许保留的注释只有两类：

- 输入辅助提示
- 风险 / 成本提示

不允许的注释：

- 技术实现解释
- 系统为什么这样工作
- 开发式说明文
- 重复性的指导语

### 5.3 中间过程规则

中间过程默认折叠。

可以展示的前提：

- 用户主动点击“查看生成依据”
- 用户主动点击“查看脚本 / 分镜”
- 当前任务处于高成本确认前
- 当前结果明显偏离目标，需要用户纠偏

否则不展示。

## 6. 统一交互规范

### 6.1 主按钮规范

每个页面只能有一个绝对主动作。

例如：

- `生成样片视频`
- `开始检测`
- `确认生成`

次级动作必须弱化：

- 本地调试
- 查看依据
- 修改配置

### 6.2 展开规则

所有“查看更多”类信息统一使用一种方式：

- 折叠卡片
- 抽屉
- 二级页

不能有的页面用 chip 展开，有的页面用 tooltip，有的页面直接铺开。

推荐默认：

- 页面内折叠卡片

### 6.3 纠偏规则

纠偏入口统一语义：

- `结果不对，调整方向`

不要再使用多个同级但语义不统一的按钮。

例如：

- `风格不对`
- `卖点不对`
- `人设不对`

这类可以保留在展开层中，但普通用户首页不要默认占据视觉中心。

### 6.4 状态规则

状态表达统一收敛成：

- `待开始`
- `生成中`
- `待确认`
- `已完成`
- `失败`

不要在普通用户层暴露：

- CLI
- Route plan
- Prompt stage
- Skill workflow

这些只在 Creator 或展开层出现。

## 7. UGC 视频工作台专项规范

### 7.1 首屏目标

普通用户进入 `/app/agents/media` 首屏时，只需要看到：

- 一个极简输入区
- 一个结果预演区
- 一个成本 / 交付概览区

### 7.2 默认不展示

首屏默认不展示：

- 系统理解全量卡片
- 脚本完整草案
- 分镜完整列表
- 执行步骤长列表
- 技术运行策略说明

### 7.3 可展开内容

通过“查看生成依据”展开：

- 系统理解
- 脚本草案
- 分镜预演
- 方案选择依据

### 7.4 任务详情页规则

任务详情页也必须遵循：

1. 第一屏看结果
2. 第二屏看交付
3. 第三层再看过程

不能第一屏就把执行过程铺满。

## 8. Creator Studio 规范

Creator Studio 例外，但也要克制。

Creator 页面可以展示：

- Skill 配置
- 路由方案
- Prompt 配置
- 调试结果
- 中间产物

但依然要遵守：

- 同类配置同样布局
- 同类输入同样组件
- 同类状态同样表达

不能变成一页一个交互风格。

## 9. 当前页面问题清单

以当前 UGC 页面为例，存在这些问题：

1. 首屏信息过多
2. 中间结果和结果预演混在一起
3. 左中右职责不够明确
4. 说明型文字仍然偏多
5. 执行过程暴露太早
6. 交付区与结果区焦点争夺
7. 纠偏入口层级过高

## 10. 后续改造顺序

建议严格按这个顺序推进：

1. 先统一前台规范，不继续局部堆功能
2. 优先改 `/app/agents/media`
3. 再改 `/app/tasks/:id`
4. 再统一 `/app/results`
5. 最后统一 Creator Studio

## 11. 实施红线

后续任何页面改动，都必须检查以下红线：

- 是否默认展示了太多信息
- 是否把过程错当成结果
- 是否让普通用户理解技术实现
- 是否出现多套同类交互
- 是否破坏左中右职责

如果有任意一项答案是“是”，则说明页面偏离规范，需要回收。
