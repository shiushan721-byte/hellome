Frontstage Design Preview

HelloMe AI 视频任务交付平台规范预览稿

这是一张独立 HTML 原型，不接当前前端路由，也不改真实业务逻辑。这一版不再把 HelloMe 当成“泛 AI 工具”，而是按 “AI 视频任务交付平台”来定义前台体验，优先补上资金风控、人工兜底、白牌交付和任务管线这些真正影响商业闭环的界面能力。

设计 Pivot
从极简工具转为 B 端交付流水线

强调成本感知、长流程反馈和服务商可控性。

资金风控
冻结金额、扣费确认、余额感知

高成本调用前必须有交易层面的明确提示。

人工兜底
脚本 / 分镜可修改后再继续

AI 只是生成草稿，服务商必须有接管点。

白牌交付
内部视角与客户视角彻底分离

客户看到结果，服务商看到成本、废稿和毛利。

00

Universal Workbench 抽象

共性链路
Brief → Outline → Draft → Render → Delivery

无论是短视频、PPT、网站还是长文，系统都应抽象成统一生产链路。

壳与心分离
Panel 壳固定，Canvas 内容可插拔

工作台的壳层、状态层、动作层固定，内部内容随模态自由切换。

跨模态一致性
Generate / Retry / Approve / Download 始终同位

换 Agent 不换习惯，让 HelloMe 真正像高级生产力平台而不是包壳网页。

01

核心原则

1

同一类功能只用一种交互样式，避免一个页面里同时出现多个解释体系。

2

普通用户默认先看结果，不先看系统过程，也不先做复杂配置。

3

信息默认收起，只有用户主动点击时才展开依据、脚本、日志或成本细节。

4

固定左中右三栏分工，左边输入，中间结果，右边状态与交付，避免模块混杂。

02

模块栈顺序

L1 页面框架

顶栏、侧栏、标签栏稳定存在，不让用户每进一个功能就重新学习导航。

L2 工作台骨架

桌面端是固定三栏；移动端不再粗暴堆叠，而是“预览在前，输入与导出切换”。

L3 页面内容

只展示当前阶段必须做的事，其他信息放到按需展开层。

L4 创作者例外层

调试、参数结构、版本切换只在 Creator Studio 里展示，不进入普通用户前台。

15

HelloMe UX Constitution

维度一
容器与空间

解决“这个内容该放在哪里”，核心目标是控制打断感和聚焦成本。

Modal / Dialog强阻断

只给高危、短动作、必须聚焦的场景，绝不塞长滚动表单，也不允许弹窗套娃。

HelloMe: 扣费确认、删除资产、重命名任务
Drawer / Slide-over复杂上下文

用于需要参考底层页面的复杂操作或长表单，不适合一句话确认。

HelloMe: 任务执行日志详情、模型高级参数配置
Popover / Tooltip轻信息

Popover 可带少量操作，Tooltip 只允许纯文本解释，不放链接和长说明。

HelloMe: 余额气泡卡片、CFG Scale 提示文案
维度二
数据录入与选择

解决“如何输入最高效”，核心是按选项数量和是否即时生效来选组件。

Switch / Toggle即时生效

只给即时改变系统状态的设置，不放在提交后才生效的表单里。

HelloMe: 开启脱敏模式、隐藏生成成本
Checkbox / Chips / Select按数量决策

2-4 个单选用 Chips；5 个以上用 Select；10 个以上必须带搜索。

HelloMe: 画幅比例、平台选择、音色选择、大模型选择
Slider / Tags Input连续值 / 多标签

用户对程度敏感用 Slider；多个并列短词用 Tags Input。

HelloMe: 视频时长、相似度、目标人群标签
维度三
状态与反馈

解决“系统如何说话”，特别是缓解 AI 生成时的等待焦虑与不确定感。

Toast / Banner轻提示 / 常驻警告

成功通知走 Toast；高优先级余额不足、权限问题走 Banner 常驻提示。

HelloMe: “链接已复制” / “余额不足 20 元，请充值”
Skeleton / Progress加载与进度

长加载先铺骨架，长任务有真实进度就给 Progress Bar，按钮内部只用 Spinner。

HelloMe: 10 个分镜骨架、视频渲染 45%
Empty State无数据

必须包含图标、友好文案和明确 CTA，不能只写“暂无数据”。

HelloMe: “还没有交付过任务” + “立即创建首个 Agent 任务”
维度四
导航与结构

解决“用户在哪里、去哪里、怎么回来”，核心是层级清晰与返回成本低。

Stepper / Timeline严格顺序

所有长任务都拆成顺序明确的步骤，并暴露 Auto / HITL / High-Cost 状态。

HelloMe: 解析需求 → 确认大纲 → 视频生成 → 整理交付
Tabs同级互斥视图

同层级内容切换用 Tabs，不要用多个连续大段内容堆叠代替。

HelloMe: 视频素材 / 文档材料 / 演示文稿
Breadcrumbs3 级以上层级

页面层级过深时必须提供面包屑，保证用户能原路返回。

HelloMe: 任务中心 > 短视频 Agent 任务 > 执行日志
维度五
数据展示

解决“信息怎么呈现最舒服”，按内容主导类型决定用表格、卡片还是列表。

Data Table结构化对比

适合可排序、可筛选、同结构行列数据，不适合看大图大视频。

HelloMe: 计费流水账单、任务耗时统计表
Card Grid视觉主导

看图、看视频、看资产时优先用卡片网格，靠视觉辨识而不是文字。

HelloMe: 资产画廊、Agent 卡片墙
List文字顺序

适合时间线、历史版本、逻辑步骤，不要硬做成卡片墙。

HelloMe: V1 / V2 / V3 版本记录
维度六
动作指令

解决“系统如何引导行动”，一个视窗内必须有清晰优先级。

Primary Button唯一主目标

一个视窗或表单内有且仅有一个主按钮，代表最高优先级任务。

HelloMe: 确认并继续 / 冻结并执行
Secondary / Ghost辅助动作

用于取消、返回、另存为草稿、重新生成等次级操作。

HelloMe: 上一步 / 另存为草稿 / 重新生成
Danger Button不可逆

所有会造成数据丢失或任务终止的操作必须显式使用危险按钮样式。

HelloMe: 中止生成任务 / 删除视频资产
维度七
AI 产品专属范式

这是 HelloMe 区别于传统 SaaS 的核心，必须把“AI 活着”的感觉设计出来。

Streaming State流式输出

文本不要等全生成完才显示，应该逐字出现，并带闪烁光标。

HelloMe: 大纲、脚本、文案、报告摘要
HITL Diff人工修改对照

服务商修改 AI 草稿时，要能看到原版与修改版的差异高亮。

HelloMe: 左侧 AI 原版 / 右侧人工修改版
Partial Reroll / Magic Wand局部重做

允许局部续写、局部重绘、智能扩写，避免因为一个错误整任务推翻重来。

HelloMe: 仅重写此段 / 仅重绘此图 / 扩写这个 Brief
决策灵魂一问

这个动作打断感强吗？决定用 Modal、Drawer，还是新开页面。

决策灵魂二问

需要让用户挑多少个选项？决定用 Chip、Select，还是 Switch。
